Key cross-cutting facts discovered
----------------------------------
- Role IDs: 1=Admin, 2=Worker, 3=Employer, 4=Agency, 5=Embassy_Source, 6=Embassy_Destination, 7=Labour.
  Mapping: ModernBackend/src/routes/authRoutes.ts (mapAppRole, roleNameToRoleId).
- JWT claims already carry userName + emailId + appRole + userKey. Login response returns userName.
  See ModernBackend/src/middleware/auth.ts:JwtClaims and /Api/token handler.
- Frontend has ONLY RoleContext (currentRole). There is NO AuthContext exposing currentUser.name.
  userName is read ad-hoc from localStorage in components/TopHeader.tsx:81 via AUTH_USERNAME_STORAGE_KEY.
- Worker→Employer relationship: stored in Tbl_Worker_PersonalInfo.Employer_Id (string, equals Tbl_User.User_Id of employer).
  Separate denormalised Tbl_Worker_EmployerInfo also exists (Employer_Name, etc).
- Worker→Agency relationship: stored in Tbl_Worker_RecruitAgent.Malaysian_Reqruitment_Agency /
  Source_Country_Requirtment_Agency (compared against user.userKey = User_Id).
- Employer→Agency relationship: NOT modelled anywhere in schema. Must be added for task 8 (Agency→Employer linking).
- Embassy nationality scoping: driven by JWT countryCode populated only at login from Tbl_Embassy.Nationality (see authRoutes.ts L266-290).
- Scope helper used by all list/report queries: ModernBackend/src/services/queryGuard.ts:buildWorkerScopeWhere.
- Attestation model already exists: Tbl_Attestation (AttestationId, Worker_Id, DocumentType, DocumentPath, Status, AdminRemarks).
- Salary dispute: NO DB model. No backend route. Frontend route only: App.tsx L236 → PlaceholderPage.
- Account page: App.tsx L235 → PlaceholderPage. No profile-photo upload endpoint.
- Blog: not present in App.tsx at all.
- Stripe: backend fully wired (subscriptionRoutes.ts), frontend PricingPage uses /Api/subscription/checkout. Needs env vars STRIPE_SECRET_KEY, STRIPE_PRICE_PRO, STRIPE_PRICE_ENTERPRISE, STRIPE_WEBHOOK_SECRET.
- Chatbot: backend chatRoutes.ts L199-207 has a minimal safety system prompt. Needs the MWMS knowledge prompt.
- Email/phone OTP: not implemented anywhere. No nodemailer/twilio deps in package.json.

     (for the filter dropdown); for agency use Tbl_Worker_RecruitAgent→Tbl_Worker_PersonalInfo→Employer_Id→Tbl_Employer.
  c. Frontend WorkerPage.tsx: drop `workersData` import and `employers` hardcoded constant.
     Populate the Employer filter and the Add Worker form employer dropdown from new endpoint.
     Ensure fields Company_Name, Name, permitExpiry (from Tbl_Worker_PermitInsurance.Permit_Expire_Date
     — already surfaced in /Api/Workers/Profile but not in List) are included in the list DTO so the
     table can show real values.
  d. Frontend AgenciesPage, AdminDashboard, views/*: audit each for imports from src/data/*.ts
